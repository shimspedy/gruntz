# Backup, account and data transfer audit — 2026-10-03

## Fixed locally

- A successful email sign-in immediately uploaded the device's state over the account's only cloud backup. New devices now stop at `needs-review` when a backup already exists. The athlete must restore it or explicitly confirm replacement; failed cloud lookups never authorize an overwrite.
- Backup upload, restore and backup deletion are serialized. Device reset and backup deletion persist an automatic-backup pause across relaunches; the existing cloud copy cannot be replaced by an empty reset device.
- Restore formerly wrote disk only and asked for a restart. The running stores could write their old state back over the restoration. Restore now validates all store envelopes first, applies existing migrations, updates live state, resets absent stores and the active workout, cancels the workout's delayed disk write and notifications, and attempts rollback if local writes fail. Subscription entitlement remains excluded from snapshots.
- Trial-start reconciliation now updates the hydrated subscription store, keeping memory and persisted state consistent.
- OTP rate limiting has a specific message; the sign-in screen validates the code length and supports resending. Local sign-out uses Supabase's local scope.
- CSV parsing now handles quoted multiline notes, reports physical line numbers, preserves zero weight and distance labels, rejects invalid calendar dates, respects explicit timezone offsets and drops empty/rest-only workouts. Aliases mapping to one exercise retain every set. Repeat imports no longer label duplicate sets as cap-related data loss. Successful imports schedule a backup.

## Backend outcome and limits

No schema change was required; the existing backend contract was verified read-only. No database rows, auth accounts, migrations or functions were changed or deployed. Actual OTP delivery, signed-in backup/restore on physical devices and successful account deletion were not exercised against a real account, because that would send email or mutate training/account data.

The CLI is installed (2.119.0), but `supabase migration list --linked` returns `ProjectRefNotLinkedError`. MCP provided the live verification instead. Live history contains four migrations (`20260923064216`, `20260923064244`, `20260923064350`, `20260923064438`); the repo contains a consolidated `20260923120000_create_backups.sql`. Their resulting backup schema matches, but history needs reconciliation before a future CLI migration push. No history repair was attempted.

Remaining design limits: one cloud snapshot per account; automatic backup is a debounced best-effort network upload, not continuous synchronization; concurrent use of multiple already-approved devices is still last-write-wins. AsyncStorage lacks transactions, so rollback cannot guarantee recovery after a process crash or persistent disk failure during replacement. CSV intentionally imports only matched library movements and does not restore workout duration, account XP or per-workout metadata.
