# Gruntz app audit and 1.9 release — October 3, 2026

This audit covers billing, workout execution and progression, run/ruck tracking, startup and navigation, reminders, account backups, data transfer, reset/recovery, bundled content and release configuration. The user authorized fixing issues, uploading to App Store Connect and submitting for review. It is not a claim that every device, network condition or App Store transaction has been tested.

The subsequent [outdoor activities release](activities-2026-10-03.md) supersedes this report's foreground-only GPS limitation and build-37 submission state. The billing, workout and data fixes below are also included in that replacement build.

## Fixes

- Billing now retries failed pricing loads, supports annual-only offerings, checks Pro before reporting purchase success, distinguishes pending approval, preserves known access during transient errors and refreshes existing subscribers during the trial. Development builds exercise real gating unless explicitly opted into a local bypass. Subscription-management failures are actionable. See [billing detail](audit-2026-10-03-billing.md).
- Workout starts preserve active sessions and convert prior weights to the selected unit. Partial working sets count in logs, duplicate completion is guarded, invalid/blank sets cannot be checked, set removal retains reachable targets, and exercise replacement cannot relabel completed history. Library days require complete working sets and credit the original plan. Recovery days cannot launch empty sessions.
- GPS/sensor setup is protected against duplicate requests and subscriptions resolving after cancellation. Pauses exclude movement and elapsed time, inaccurate fixes cannot anchor distance, save captures final values, and native back navigation saves once. The foreground-only tracker pauses when backgrounded and explains this in the UI.
- Backups require explicit consent before a new device overwrites an existing cloud copy. Restore validates payloads, replaces live state as well as storage, cancels pending workout writes, and attempts rollback on local storage failure. CSV round trips handle multiline notes, zero weights, timezone offsets, invalid dates and aliases. See [data detail](audits/data-2026-10-03.md).
- Local data deletion resets every live training store, keeps store-managed subscription/trial state, and pauses uploads so an empty phone cannot overwrite cloud training. Crash recovery clears transient memory and disk while preserving run history.
- Startup now waits for training stores, protects unreadable profile/program/subscription blobs from default-state writes, offers a retry instead of an endless boot screen, and proceeds with fallback fonts if font loading stalls. Notification launch destinations take precedence over saved navigation and consumed responses are cleared.
- Reminder enabling opens the scheduling gate before scheduling, reminder days update with training preferences, and disabled reminders cannot schedule new rest alerts.
- Added the regression suite to `npm run check` and a GitHub Actions check workflow. Applied Expo-recommended patch updates and compatible dependency fixes, without forcing incompatible framework downgrades.

## Limits and follow-up

- Real StoreKit purchase, renewal, cancellation and restore on an authenticated sandbox device still require transaction testing. Mocked billing tests and live product configuration checks cannot prove every store transaction.
- Real GPS accuracy, notification delivery, physical-device background behavior and OTP email delivery are not established by unit tests. GPS remains foreground-only; an OS-terminated run is not recoverable.
- Existing backup users confirm replacement or restore once to enable automatic uploads under the new protection. Multiple approved devices remain last-write-wins; there is one cloud snapshot per account.
- `npm audit fix` resolved compatible advisory paths. Remaining advisory paths are primarily Expo/React Native build tooling; the audit suggests incompatible SDK/framework downgrades. No forced downgrades were applied. Do not interpret a passing functional suite as a dependency-security clearance.
- Native UI coverage was observational for welcome/onboarding, live pricing, a library workout day and the run screen. Concurrent simulator interaction prevented a controlled end-to-end workout logging/finish smoke test; automated workout regressions passed. Do not interpret this as a full manual sweep of every screen.
