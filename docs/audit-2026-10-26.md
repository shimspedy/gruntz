# Gruntz change audit — October 26, 2026

## Scope

Reviewed the retention implementation, its persistence and reward paths, native build support, dependency graph, and the two earlier unpushed exercise/video and watch configuration commits. The starting remote `main` was `3b97edb`; the inherited commits were `67741eb` and `dc0bcd9`.

The review covered onboarding and interrupted setup, practice isolation, billing access, modal navigation, actual workout dates, mission debriefs, test scores and retests, readiness choices, reminder scheduling, backup/restore, analytics deletion, exercise/history identity, and build reproducibility. Existing colors, fonts, components, and branding are retained.

The security follow-up starts from `c3b88a9` and resolves the remaining 11 dependency reports. Expo 57, native packages, and application behavior retain their existing versions; the changes target development and signing dependencies.

## Findings fixed

- Shorter sessions now reduce supported distance ranges as well as sets, reps, and time. Fixed courses and interval totals are preserved explicitly; time/reward estimates do not claim a reduction when the actual prescription is unchanged.
- Progress comparisons and PR XP record the movement actually performed. A shared video/history key cannot turn a different exercise, substituted movement, or unverified legacy/imported record into a claimed improvement or PR reward. Invalid units and missing load cannot be compared with weighted efforts.
- Analytics deletion is serialized with event writes and diagnostics reads, so an event arriving during deletion cannot resurrect the previous history.
- Reminder activation and time changes check native scheduling results. Failures leave reminders off and cancel older daily, weekly, trial, and rest alerts rather than reporting success.
- Weekly recap links identify the notification's delivered week, including Expo's different iOS/Android timestamp units. Opening Sunday's recap on Monday still shows the intended week.
- Attendance uses actual exercise/activity timestamps; scheduled mission identities cannot fabricate past or future training days.
- Test target preferences can be saved independently of a new measured attempt. Invalid nonempty measurements and targets are rejected instead of silently coerced or replaced.
- Clearly mismatched demonstration aliases were removed while retaining the exercise's instructions and existing history keys.
- Base Camp's onboarding, program-list, and detail labels now show the same adaptive days-per-week schedule as its actual workouts, instead of the catalog's fixed four-day default.
- Expo's iOS signing team now matches the existing EAS submit configuration. Regenerated iPhone and Watch targets retain the team required for default simulator Keychain entitlements.
- Expo's Swift interface cleanup accepts both dot and `::` C++ namespace forms. The idempotent postinstall patch preserves public declarations and is regression-tested.
- The lockfile includes the Apple target tooling's optional TypeScript 5 peer alongside the app's TypeScript 6 compiler. This fixes a clean-install failure exposed by CI's npm 10 resolver; all previously locked package versions are retained.

- Expo's two `node-forge` consumers resolve the local **`@gruntz/node-forge@1.4.0-gruntz.1` security backport**. Upstream has no patched release. The RSA file is pinned to unmerged [upstream PR #1159](https://github.com/digitalbazaar/forge/pull/1159), commit `db05494352dd3c9a5a07c5270333dcc78866cad2`; all other Node source files match the original integrity-verified package. Both actual Expo dependency resolutions are tested, preventing an unused patched copy from passing validation while an unpatched package is still loaded.
- CI now runs `npm run security:audit` for both mobile and website dependencies and fails on advisories of any severity.

Primary references: [shell-quote advisory](https://github.com/ljharb/shell-quote/security/advisories/GHSA-pqg4-j6r4-53mv), [node-forge advisory and absence of a patched release](https://github.com/advisories/GHSA-86w9-cpqp-85rv), [Zod advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [xmldom security backports](https://github.com/xmldom/xmldom/releases/tag/0.8.15), [UUID security release](https://github.com/uuidjs/uuid/releases/tag/v11.1.1), [Astro 7 upgrade guide](https://docs.astro.build/en/guides/upgrade-to/v7/).
